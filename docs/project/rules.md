# 프로젝트 규칙

## 제품 맥락

이 프로젝트는 사용자가 책을 읽으며 떠오른 생각을 **한 줄로 빠르게 기록**하고, 시간이 흐른 뒤 그 기록을 다시 발견하게 돕는 개인 독서 기록장이다. 자세한 제품 결정은 [제품 기획](../product/one-line-reading-journal.md)을 따른다.

## 작업 원칙

- 사용자의 핵심 행동은 `책 선택 → 한 줄 작성 → 선택적 감정 태그 → 저장`이다. 이 흐름의 단계와 인지 부담을 늘리지 않는다.
- 기본 경험은 사적이고 조용하다. 소셜 경쟁, 공개, 알림은 명시적 선택 없이 강제하지 않는다.
- 완독 여부와 관계없이 기록을 남길 수 있어야 한다.
- 접근성을 기본 품질로 취급한다. 의미 있는 HTML, 키보드 조작, 충분한 대비, 입력 요소의 라벨을 제공한다.
- 모바일 우선으로 설계하되, 넓은 화면에서도 읽기와 기록에 집중할 수 있게 한다.

## 코드 품질과 검증

- TypeScript의 타입 안정성을 유지한다. `any`와 불명확한 타입 단언은 피하고, 도메인 타입을 명시한다.
- 기존 컴포넌트·스타일의 패턴을 먼저 재사용한다. 같은 역할의 코드와 상수는 중복하지 않는다.
- 사용자에게 보이는 문구는 자연스러운 한국어로 작성하고, 빈 상태·오류 상태·로딩 상태를 함께 고려한다.
- 변경 규모에 맞춰 `npm run lint`, `npm run build` 또는 관련 테스트를 실행한다. 실행하지 못했다면 이유를 명확히 남긴다.

## 문서화

- 사용자 흐름, 기능 범위, 용어가 바뀌면 제품 기획 문서를 갱신한다.
- 폴더 책임, 상태 경계, 데이터 계약이 바뀌면 아키텍처 규칙을 갱신한다.
- 결정의 배경이 코드만으로 드러나지 않을 때는 관련 도메인 문서에 짧게 기록한다.

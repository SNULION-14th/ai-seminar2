# 검증 기준

이번 검토 결과는 [release-review.md](release-review.md)에 기록했다.

## 자동 검사

```bash
npm ci
npm run check
npm audit
```

`check`는 린트, 테스트, TypeScript 검사·웹 빌드, 플러그인 빌드를 실행한다. GitHub Actions에서도 같은 검사를 실행한다. 원격 CI 성공 여부는 실제 PR의 실행 결과로 확인한다.

| 동작 | 통과 기준 |
| --- | --- |
| 레퍼런스 가져오기 | 중복 이름과 작은 누락을 허용하고 기본값·원문·프레임 자료로 보완한다. 그릴 수 없는 레이어만 제외하며 경고를 표시한다 |
| 레퍼런스 한계 | JSON 파손·지원하지 않는 버전·프레임 부재·잘못된 판형·자원 상한 초과는 거부한다 |
| 레퍼런스 호환 | 완전한 명세의 값·순서·해시를 보존하며 보완한 명세를 다시 읽어도 값과 해시가 달라지지 않는다 |
| 원본 측정 | 원본 문구·범위 서식·크기·부모 자동 배치를 변경하지 않으며 임시 복제본을 정리한다 |
| 프레임 선택 | 정리용 프레임·그룹 안의 카드도 읽을 수 있으며 화면에 표시한 프레임과 실제로 읽는 프레임이 일치한다 |
| 브리프 저장 | 동일 입력으로 다시 저장해도 새 작업 ID를 발급한다 |
| 결과 자료 검증 | 서버에 저장된 브리프와 결과의 ID·레퍼런스 해시·장수·순서가 맞는지 확인한다 |
| 결과 조회 | 화면의 레퍼런스·입력·작업 ID가 달라도 저장 결과를 바로 표시하고 차이만 안내한다. 폼은 바꾸지 않으며, 미리보기·검증·복사는 결과의 레퍼런스와 적용 방식을 사용한다 |
| 화면 편집 | 입력·레퍼런스·모드를 바꾸면 이미 표시한 결과는 유지하고 차이 안내를 갱신한다. 늦은 응답은 무시하고 새 브리프 저장 시 이전 화면 결과를 비운다 |
| Markdown 파일 | 늦게 읽힌 파일이 최신 편집을 덮지 않고 읽기 중에는 브리프 저장을 막는다 |
| 로컬 서버 | 외부 출처의 요청과 비공개 파일의 직접 HTTP 접근을 거부한다 |
| 배치 방식 | 유지 모드는 전체, 본문 재구성은 첫·끝장만 원본 형식을 따르며 전체 재구성은 모든 장을 새로 설계한다 |
| 가독성 | 잘못된 색·글꼴, 넘침·겹침·화면 밖 배치·읽기 어려운 대비를 검사한다 |
| Figma 생성 실패 | 이번 실행의 새 노드만 정리하고 원본을 보존한다 |
| 저장값 복원 | 잘못된 브라우저 저장값은 해당 필드만 기본값으로 복원한다 |

## Figma에서 수동 확인

자동 테스트는 Figma API 모형을 사용하므로 다음 확인을 대체하지 않는다.

1. 굵기·색이 섞인 텍스트와 자동 배치 프레임을 읽은 뒤 원본이 유지되는지 확인한다.
2. 생성된 결과를 가져와 설치된 글꼴의 줄바꿈과 실제 크기를 확인한다.
3. 생성을 빠르게 반복해도 중복 작업이 시작되지 않는지 확인한다.
4. 사진의 밝기와 텍스트 가독성, 프레임 순서, PNG 내보내기를 확인한다.

## 공개할 파일

코드, `package-lock.json`, 문서와 익명 예시만 포함한다. `.env`, `brief/`, `renders/`, 개인 MCP 설정과 빌드 결과는 제외한다. 이 예외 목록은 `.gitignore`로 관리하며 이미 추적된 파일에는 소급 적용되지 않는다.

과제 제출 전 PR 본문에는 실제 사용한 MCP 2종의 이름·목적·결과 링크를 적는다. Figma 개발 플러그인 자체를 MCP 사용으로 기록하지 않는다.

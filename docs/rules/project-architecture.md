# NBA Game Night Log 프로젝트 및 아키텍처 규칙

## 기술 기준

- React 19, TypeScript, Vite를 사용한다.
- 기본 UI 아이콘은 이미 설치된 `lucide-react`를 사용한다.
- 과제 MVP에 필요한 기능은 새 의존성보다 React 기본 기능과 브라우저 API를 우선한다.
- 외부 백엔드·인증·데이터베이스는 도입하지 않는다.

## 디렉터리 구조

기능이 추가되면 아래 구조로 분리한다. 단, 아주 작은 MVP에서는 빈 디렉터리나 지나친 추상화를 만들지 않는다.

```text
src/
├── components/       # 여러 화면에서 재사용하는 UI 컴포넌트
├── features/         # 화면 또는 도메인별 기능
│   ├── home/
│   ├── diary/
│   ├── player/
│   └── archive/
├── data/             # NBA 경기, 선수, 샘플 데이터
├── lib/              # localStorage, 이미지 처리, 통계 계산 등 순수 유틸리티
├── types/            # 도메인 TypeScript 타입
├── App.tsx           # 화면 전환과 최상위 조합
├── App.css           # 앱 전용 레이아웃 및 컴포넌트 스타일
└── index.css         # 전역 토큰, 리셋, 글꼴 및 기본 스타일
```

## 컴포넌트 규칙

- 한 컴포넌트는 한 화면 영역 또는 하나의 사용자 행동을 책임진다.
- `App.tsx`는 페이지 전환, 전역 일기 상태, 최상위 레이아웃만 조합한다.
- 입력·저장 로직이 있는 `DiaryForm`과 표시만 하는 `DiaryCard`를 분리한다.
- 경기·선수 데이터를 UI 형태로 변환하는 규칙은 JSX 안에 직접 작성하지 않고 `lib/`의 함수로 분리한다.
- 컴포넌트 props에는 `any`를 사용하지 않고, 도메인 타입을 재사용한다.
- 필요하지 않은 전역 상태 관리 라이브러리는 추가하지 않는다.

## 상태와 데이터 흐름

```text
샘플 NBA 경기·선수 데이터
        ↓
홈의 경기 선택 / 선수 관전 포인트
        ↓
관람 일기 작성 폼
        ↓
React 상태
        ↓
localStorage 저장
        ↓
아카이브 목록 및 통계 계산
```

- `DiaryEntry` 타입은 `docs/rules/domain-rules.md`의 필드를 단일 기준으로 한다.
- 일기 배열은 앱 최상위 상태에서 관리하고, 화면에는 props와 콜백으로 전달한다.
- localStorage 읽기·쓰기와 데이터 유효성 검사는 `lib/storage.ts`에 둔다.
- 통계 계산은 `lib/statistics.ts`의 순수 함수로 구현한다.
- 날짜·팀·선수·경기 샘플 데이터는 `src/data/`에 둔다. UI 컴포넌트 내부에 하드코딩하지 않는다.
- NBA 데이터 MCP 연결 전에는 `src/data/nba.ts`의 샘플 데이터를 사용하고, MCP 결과를 연결할 때도 UI가 기대하는 데이터 형태를 유지한다.

## 이미지 처리 규칙

- 사진은 최대 3장, 티켓은 최대 1장으로 제한한다.
- 이미지 파일 형식과 개별 용량 제한을 업로드 직후 검증한다.
- 저장 전에 브라우저에서 이미지 크기를 축소해 localStorage 용량 초과 가능성을 줄인다.
- `FileReader` 실패나 저장 공간 부족은 화면에서 복구 가능한 오류 메시지로 보여준다.
- 이미지 data URL을 렌더링할 때는 사용자 파일명 대신 안전한 대체 텍스트를 제공한다.

## 스타일과 접근성 규칙

- 색상, 간격, 둥근 모서리, 그림자는 CSS 변수로 정의해 일관성을 유지한다.
- 모바일 우선으로 구현하고, 넓은 화면에서는 콘텐츠 최대 너비를 제한한다.
- 버튼에는 동작을 설명하는 텍스트 또는 `aria-label`을 제공한다.
- 아이콘만 있는 버튼에는 툴팁 또는 접근 가능한 이름을 제공한다.
- 키보드만으로 저장, 수정, 삭제, 이미지 선택에 접근할 수 있어야 한다.
- 색상만으로 승패·오류·선택 상태를 구분하지 않는다.

## 오류 처리 규칙

- 필수 입력 누락은 해당 필드 근처에 한국어 오류 문구로 안내한다.
- localStorage 읽기 실패 시 빈 목록으로 앱을 중단하지 말고, 기록을 복구할 수 없음을 알린다.
- 데이터가 없을 때는 빈 화면 대신 다음 행동을 제안하는 Empty State를 표시한다.
- 브라우저 새로고침 후에도 저장된 기록과 통계가 일관되게 복원되어야 한다.

## 검증 규칙

변경 후 다음을 수행한다.

```bash
npm run lint
npm run build
```

또한 브라우저에서 아래 흐름을 확인한다.

1. 관람 일기를 텍스트만으로 저장한다.
2. 사진과 티켓을 포함한 일기를 저장한다.
3. 새로고침 후 기록이 남아 있는지 확인한다.
4. 아카이브의 경기 수와 승률이 올바른지 확인한다.
5. 일기를 수정·삭제한 뒤 통계가 갱신되는지 확인한다.

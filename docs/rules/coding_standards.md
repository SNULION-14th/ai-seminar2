# 📏 [개발 규칙] 코딩 표준 및 엔지니어링 가이드라인
> **문서 버전:** v1.0
> **적용 대상:** 프로젝트 내 모든 TypeScript / React 코드 및 리소스

---

## 1. 언어 및 런타임 규칙 (TypeScript)

1. **Strict Type Safety:**
   * `any` 타입 사용은 엄격히 금지합니다. 불가피한 경우 `unknown`을 사용하고 타입 가드(Type Guard)로 좁힙니다.
   * `tsconfig.json`의 `strict: true` 옵션을 100% 준수합니다.
2. **명시적 인터페이스 분리:**
   * Props와 Domain Entity는 명확한 `interface` 또는 `type`으로 정의합니다.
   * 컴포넌트 Props는 해당 컴포넌트 파일 상단에 정의하거나, 복잡할 경우 `types/`로 분리합니다.
3. **불변성 (Immutability) 유지:**
   * 배열 및 객체 상태 수정 시 원본 객체를 직접 변경(Mutation)하지 않고 스프레드 연산자 또는 불변 업데이트 방식을 준수합니다.

---

## 2. React 19 컴포넌트 개발 가이드

1. **함수형 컴포넌트 & 화살표 함수:**
   * 컴포넌트는 간결한 함수형으로 작성하며, 단일 책임 원칙(SRP)을 준수합니다.
   * 컴포넌트 파일당 하나의 메인 컴포넌트만 기본(default) export 또는 named export로 제공합니다.
2. **비즈니스 로직 분리 (Custom Hooks):**
   * UI 컴포넌트 내부에는 렌더링 로직과 단순 UI 이벤트 핸들러만 위치시킵니다.
   * 복잡한 계산, 비동기 통신, 상태 전이 로직은 반드시 `use[Feature]` 형태의 커스텀 훅으로 추출합니다.
3. **렌더링 최적화:**
   * 자주 변경되는 입력 필드(텍스트 인풋)와 목록 렌더링 영역의 상태를 분리하여 불필요한 전체 리렌더링을 차단합니다.
   * 순수 계산 비용이 큰 로직은 `useMemo`, 자식 컴포넌트로 전달되는 핸들러는 `useCallback`을 적절히 활용합니다.

---

## 3. UI/UX 및 디자인 표준

1. **모바일 퍼스트 (Mobile-First):**
   * 메신저 앱 특성을 반영하여 기본 레이아웃은 모바일 뷰포트(375px ~ 430px 기준)에 최적화하며, 데스크톱 뷰에서는 중앙 카드(Max-width 480px) 형태로 반응형 처리합니다.
2. **터치 타깃 및 접근성:**
   * 모든 터치/클릭 가능한 버튼 및 아이콘은 최소 44x44px의 터치 영역을 확보합니다.
   * 아이콘 단독 버튼에는 반드시 `aria-label`을 지정하여 접근성을 준수합니다.
3. **여백 및 타이포그래피:**
   * 스위스 미니멀리즘 스타일에 맞게 군더더기 없는 Sans-serif 폰트 스택을 사용하고, 8pt 그리드 시스템(4px, 8px, 16px, 24px)에 기반한 패딩/마진을 적용합니다.

---

## 4. 에러 처리 및 회복성 (Resilience)

1. **오프라인 및 네트워크 오류 복구:**
   * 네트워크가 단절되어도 UI가 멈추지 않아야 하며, 미전송 메시지는 '전송 실패' 아이콘 및 '재시도(Retry)' 버튼을 노출합니다.
2. **Graceful Degradation:**
   * 이미지 로딩 실패 시 깨진 이미지 아이콘 대신 세련된 플레이스홀더를 제공합니다.
   * 빈 화면(Empty State)에서도 사용자에게 명확한 다음 액션(예: "새 대화를 시작해보세요 [+ 버튼]")을 안내합니다.

---

## 5. 커밋 및 협업 규칙 (Conventional Commits)

* `feat`: 새로운 기능 추가 (예: `feat: 대화방 포커스 모드 토글 추가`)
* `fix`: 버그 수정 (예: `fix: 메시지 전송 후 인풋 초기화 오류 수정`)
* `refactor`: 프로덕션 코드 리팩터링
* `style`: 코드 스타일 및 포맷팅 (로직 변경 없음)
* `docs`: 문서 생성 및 수정 (예: `docs: ANTIGRAVITY.md 라우터 색인 업데이트`)

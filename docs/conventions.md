# [Conventions] 코딩 컨벤션 및 개발 표준

이 문서는 프로젝트 개발 시 지켜야 할 TypeScript, React 19, 스타일링 및 협업 규칙을 정의합니다.

---

## 1. 언어 및 커뮤니케이션 규칙
* **생각은 영어(Thinking in English), 사용자 응답은 항상 한국어(Korean)**로 작성합니다.
* 커밋 메시지 및 코드 주석은 영어(Conventional Commits)를 기본으로 권장하며, 기획/설계 문서는 한국어로 작성합니다.

---

## 2. TypeScript 개발 규칙
1. **`any` 사용 절대 금지:**
   * 불가피한 동적 데이터는 `unknown`을 사용하고 타입 가드(Type Guard)로 검증합니다.
2. **명시적인 반환 타입:**
   * 커스텀 훅과 비즈니스 로직 함수는 반환 타입을 명시적으로 선언합니다.
3. **인터페이스 vs 타입 별칭:**
   * 데이터 객체 모델은 `interface`를 우선하고, 유니온 타입이나 유틸리티 타입 조작 시에는 `type`을 사용합니다.
4. **Strict 모드 준수:**
   * `strictNullChecks`를 준수하며, 옵셔널 체이닝(`?.`) 및 null 병합 연산자(`??`)를 적극 활용합니다.

---

## 3. React 19 컴포넌트 원칙
1. **단일 책임 원칙 (Single Responsibility):**
   * 한 컴포넌트는 한 가지 시각적/기능적 책임만 가집니다. 파일 길이가 150줄을 초과하면 서브 컴포넌트나 훅으로 분리합니다.
2. **비즈니스 로직과 뷰의 분리:**
   * JSX 내부에서 복잡한 상태 계산이나 비동기 로직을 수행하지 않고, 커스텀 훅(`src/hooks/`)으로 캡슐화합니다.
3. **Props 인터페이스 명명:**
   * 컴포넌트 Props는 `${ComponentName}Props` 형식으로 선언합니다 (예: `TaskItemProps`).
4. **성능 최적화:**
   * 리스트 렌더링 시 고유한 `id`를 `key`로 사용하며, 불필요한 인라인 함수/객체 생성을 최소화합니다.

---

## 4. 스타일링 및 인터랙션 규칙
1. **디자인 토큰 활용:**
   * 색상, 폰트 크기, 마진, 그림자, 애니메이션 지속 시간 등은 하드코딩하지 않고 CSS 변수(`var(--color-primary)`)를 참조합니다.
2. **반응형 & 모바일 퍼스트:**
   * 모바일 화면(360px ~ 430px)을 기본으로 설계하고, 태블릿/데스크톱은 중앙 컨테이너(최대 너비 480px) 형태로 쾌적하게 렌더링합니다.
3. **접근성(a11y) 보장:**
   * 아이콘 단독 버튼에는 반드시 `aria-label`을 부여하고, 키보드 포커스 링을 유지합니다.

---

## 5. Git 커밋 메시지 컨벤션 (Conventional Commits)

```text
<type>(<scope>): <subject>

[예시]
feat(task): Top 3 포커스 태스크 고정 기능 구현
fix(storage): 로컬스토리지 JSON 파싱 예외 처리
style(header): 진행률 바 애니메이션 easing 속성 개선
docs(prd): 나이트 클린업 인터랙션 요구사항 구체화
refactor(hooks): useTodos 내 정렬 로직 순수 함수 분리
```

* **feat:** 새로운 기능 추가
* **fix:** 버그 수정
* **refactor:** 코드 구조 개선 (기능 변경 없음)
* **style:** 코드 스타일, CSS/UI 수정
* **docs:** 문서 추가 및 수정
* **chore:** 빌드 설정 및 패키지 관리

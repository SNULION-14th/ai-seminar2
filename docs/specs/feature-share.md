# 기능 스펙 — 기록 & 공유 (Share)

> Status: **Approved** (2026-09-24) · 마일스톤: M3 · 관련: [feature-track.md](feature-track.md), [design-system.md](design-system.md)

## 1. 목적

633km를 달린 이야기를 **한 장의 카드와 하나의 링크**로 남긴다. 서버 없이도 친구에게 보여 줄 수 있어야 한다.

## 2. 사용자 스토리

- P3로서, 완주하면 경로와 도장이 담긴 예쁜 이미지를 인스타그램에 올리고 싶다.
- P2로서, 지금까지 어디까지 달렸는지 진행 중 상태도 공유하고 싶다.
- 링크를 받은 친구로서, 앱을 설치하거나 가입하지 않고 기록을 보고 싶다.

## 3. 요구사항

| ID | 요구사항 | 우선순위 |
| --- | --- | --- |
| SHR-01 | **기록 화면**: 누적 진행 지도(달린 구간 강조), 도장판(전체 인증센터 격자, 찍은 것만 컬러), 일지 타임라인(일자별 거리·메모) | P0 |
| SHR-02 | **공유 카드 이미지**: 1080×1350(4:5) PNG. 구성: 강줄기 라인아트(달린 부분만 컬러) + 총거리/일수/도장 수 + 기간 + 서비스 워터마크. 템플릿 2종(한지 라이트 / 밤하늘 다크) | P0 |
| SHR-03 | 카드 렌더링: DOM → Canvas 변환(`html-to-image` 등) 또는 Canvas 2D 직접 그리기. 한글 웹폰트가 이미지에 제대로 들어가야 한다 | P0 |
| SHR-04 | **공유 링크**: 요약 데이터(도장 목록, 일자별 거리, 기간, 닉네임, 단순화한 궤적)를 JSON → 압축(`lz-string`) → URL 해시(`#/s/<payload>`)로 인코딩한다. 서버 저장은 하지 않는다 | P0 |
| SHR-05 | **공유 페이지**: 해시를 디코딩해 읽기 전용 기록 화면을 렌더링한다. 받은 사람 기기의 데이터는 건드리지 않는다. 하단에 "나도 계획 세우기" CTA | P0 |
| SHR-06 | 공유 수단: Web Share API(모바일, 이미지 파일 포함) → 미지원이면 이미지 다운로드 + 링크 복사로 대체 | P0 |
| SHR-07 | 개인정보: 공유 전 "출발/도착 지점 정밀 궤적 숨기기" 옵션(기본 ON). 켜면 궤적 대신 인증센터 단위 구간만 포함한다 | P1 |
| SHR-08 | 완주 연출: 마지막 도장(낙동강하굿둑)을 찍으면 강줄기가 바다로 흘러드는 완주 애니메이션 후 공유 카드 만들기로 안내한다 | P1 |
| SHR-09 | 데이터 백업: 전체 로컬 데이터를 JSON 파일로 내보내고 다시 가져올 수 있다(기기 변경 대비) | P1 |

## 4. 제약

- URL 길이: 공유 링크는 **2,000자 이하**를 목표로 한다. 넘으면 궤적 정밀도를 단계적으로 낮춘다(Douglas-Peucker 허용 오차를 키움) → 그래도 넘으면 궤적을 빼고 구간 단위로만 표현한다.
- 공유 페이지는 해시 payload를 신뢰할 수 없는 입력으로 다룬다. 스키마 검증에 실패하면 "손상된 링크" 화면을 보여 주고, payload 내용을 `innerHTML`로 넣지 않는다.

## 5. 수용 기준

- [ ] 도장 5개 이상 찍힌 상태에서 공유 카드 PNG가 1080×1350으로 저장되고 한글이 깨지지 않는다
- [ ] 생성한 공유 링크를 시크릿 창에서 열면 같은 요약(거리, 도장 수, 기간)이 보인다
- [ ] 완주 수준의 데이터(27개 도장, 5일)로 만든 링크가 2,000자 이하이다 (단위 테스트)
- [ ] 임의로 변조한 해시로 접근하면 크래시 없이 "손상된 링크" 화면이 나온다
- [ ] 공유 페이지를 열어도 받은 사람의 로컬 데이터(계획/기록)가 바뀌지 않는다
- [ ] JSON 백업을 내보낸 뒤 데이터를 초기화하고 다시 가져오면 원래 상태로 복원된다

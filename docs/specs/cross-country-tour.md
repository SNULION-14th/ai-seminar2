# 강따라 633 — 자전거 국토종주 동반자 (제품 개요)

> Status: **Approved** (2026-09-24) · Owner: hanjoonbae · Last updated: 2026-09-24
> 서비스명: **강따라 633** (확정) · 서비스 언어: **한국어 전용**

## 1. 한 줄 정의

인천 아라서해갑문에서 부산 낙동강하굿둑까지 약 633km, 강을 따라 달리는 국토종주 라이더를 위해 **떠나기 전(계획) · 달리는 중(트래킹) · 다녀온 뒤(공유)** 를 하나의 흐름으로 이어 주는 모바일 우선 웹서비스.

## 2. 문제와 기회

| 시점 | 지금 라이더가 겪는 불편 | 강따라 633이 주는 것 |
| --- | --- | --- |
| 계획 | 블로그·카페 글을 모아 엑셀로 일정 짜기. 하루 몇 km, 어디서 자야 할지 감으로 결정 | 일수·체력만 넣으면 인증센터 단위로 일자별 구간과 숙박 거점을 자동 제안 |
| 트래킹 | 범용 운동 앱은 "국토종주 진행률"을 모름. 다음 인증센터까지 몇 km 남았는지 알기 어려움 | 633km 중 현재 위치, 다음 인증센터까지 남은 거리, 계획 대비 앞섬/뒤처짐 |
| 공유 | 완주 후 인증수첩 사진 한 장으로 끝남 | 경로 라인아트 + 찍은 도장 + 기록이 담긴 공유 카드와 읽기 전용 공유 링크 |

## 3. 타깃 사용자

- **P1. 첫 종주 준비생**: 20-30대, 4-6일 일정. 계획 기능이 가장 중요하다.
- **P2. 주말 끊어 타기족**: 구간별로 여러 번 나눠 달린다. 누적 진행률과 인증센터 체크가 중요하다.
- **P3. 완주 후 자랑러**: 기록을 예쁘게 남기고 싶다. 공유 기능이 가장 중요하다.

## 4. 범위

### In scope (v1)

- 계획: 일정 자동 분할, 고도 프로필, 난이도 구간 안내, 준비물 체크리스트, 캘린더 내보내기(.ics) → [feature-plan.md](feature-plan.md)
- 트래킹: GPS 기반 라이딩 기록, 인증센터 도장, 진행률, 시뮬레이션 모드 → [feature-track.md](feature-track.md)
- 공유: 공유 카드 이미지, URL 기반 읽기 전용 공유 페이지 → [feature-share.md](feature-share.md)
- 자연친화적·인터랙티브 디자인 시스템 → [design-system.md](design-system.md)
- 한국어 전용 UI (모든 문구, 날짜·숫자 형식은 `ko-KR`)

### Non-goals (v1에서 하지 않음)

- 회원가입/로그인, 서버 DB (모든 데이터는 기기 로컬 저장)
- 공식 인증(자전거행복나눔 인증수첩/앱)을 대체하는 것. 이 서비스의 도장은 개인 기록용이다
- 네이티브 앱 수준의 백그라운드 GPS (웹 플랫폼 한계를 UI에 명시)
- 실시간 다중 사용자 위치 공유, 소셜 피드
- 턴바이턴 내비게이션
- 다국어 지원 (한국어만 제공)
- 역방향(부산→인천) 일정, 일지 사진 첨부, PWA(오프라인 캐시·홈 화면 추가)
- 자체 MCP 서버

## 5. 핵심 사용자 흐름

```text
[홈: 강줄기 인트로]
   ├─▶ [계획] 조건 입력 → 일정 생성 → 일자별 구간 확인/조정 → 저장 / .ics 내보내기
   ├─▶ [트래킹] 오늘의 구간 선택 → 라이딩 시작 → 도장 찍기 → 라이딩 종료 → 일지 저장
   └─▶ [기록/공유] 누적 진행 지도 → 공유 카드 생성 → 이미지 저장 / 링크 복사
```

## 7. 성공 기준 (데모 기준)

- 모바일 뷰포트(390×844)에서 계획 → 트래킹(시뮬레이션) → 공유 흐름이 새로고침 후에도 데이터 유실 없이 끝까지 이어진다.
- 개발 과정에서 MCP 3종(Context7, Playwright, Google Calendar)을 실제로 사용했고, 그 흔적(설정 파일, 스크린샷, 검증 로그)이 레포에 남아 있다.
- 기능 구현을 에이전트 팀(A2A)으로 진행했고, 에이전트 간 메시지 로그가 레포에 남아 있다.
- `npm run build`와 `npm run lint`가 통과한다.
